# Центр «Практика ТН» — перенос прототипа в отдельный сайт

Этот файл — задание для Claude Code. Читай его первым в каждой сессии.

## Что это
Учебная платформа технадзора (ТН) для строительства ЖК компании Engineering Services.
Два уровня доступа:
- **Наставник** (mentor/owner) — готовит уроки: лекция, фото, упражнения «Найди дефект» с отметками,
  нормативы, варианты для замечания DES, вопросы блиц-теста; редактирует главную; ведёт журнал
  абитуриентов и открывает им разделы.
- **Абитуриент** (trainee) — регистрируется (ФИО, специальность, уровень ТН), проходит уроки по шагам,
  результаты с датами пишутся в журнал.

Рабочий прототип: `prototype/index.html` (один файл, ~300 КБ). Исходники прототипа по частям —
`prototype/src/` (собираются `build.py`). Прототип работал на claude.ai, где хранилище и роли давала
платформа через `window.claude.use(...)`. Здесь этого нет — заменяем на Supabase.

## Целевой стек (бесплатно)
- **Supabase (Free)**: Postgres + Auth (вход по e-mail) + Storage (фото) + Realtime.
- **Хостинг статики**: Cloudflare Pages (бесплатно, разрешено коммерческое использование).
  Альтернатива — Netlify. Vercel Hobby не использовать: тариф только для некоммерческих проектов.
- Код: оставляем vanilla JS одностраничного приложения (без фреймворка) на этапе 1 — так перенос
  займёт минимум времени. Сборка — Vite (только чтобы подключить `@supabase/supabase-js` и env).

## Этап 1 — перенос 1:1 (цель: сайт работает так же, как прототип)
1. Создать проект Vite (vanilla). Перенести код прототипа из `prototype/src/` в модули
   (`src/data/lessons.js`, `src/engine/*.js`, `src/ui/*.js`, `src/styles.css`), сохранив поведение.
   Не переписывать логику уроков — только разнести по файлам.
2. Написать `src/platform.js` — адаптер, который реализует **тот же интерфейс**, что ожидает код
   (см. «Контракт адаптера» ниже), поверх Supabase. В коде заменить `window.claude.use(...)` на
   этот адаптер. Это главный кусок работы.
3. Схема БД — `supabase/schema.sql` (таблица `docs` хранит документы по путям, как в прототипе;
   `profiles.role` — роли; RLS уже прописан; bucket `assets` для фото).
4. Вход: страница входа по e-mail (magic link или пароль) через Supabase Auth. Без входа сайт
   показывает только экран входа.
5. `blobUrl(id)` → публичный URL Supabase Storage: `${SUPABASE_URL}/storage/v1/object/public/assets/${id}`.
6. Пароль наставника из прототипа (`cms/main.passHash`) больше не нужен: доступ наставника определяется
   `profiles.role`. Экран пароля убрать; кнопка «Кабинет наставника» видна только mentor/owner.
7. Импорт данных: скрипт `scripts/import.mjs` (Node, service-role key из `.env`, НЕ коммитить):
   - каждый JSON из `data-export/` → строка `docs` с `path` = путь файла без `.json`
     (например `data-export/cms/main/lessons/A1.json` → `cms/main/lessons/A1`);
   - каждый файл из `data-export/assets/` → Storage bucket `assets` с именем = id (без расширения
     в ключе или с `.jpg` — главное, чтобы `blobUrl(id)` совпадал);
   - `trainees/*` и `cms/main/access/*` из прототипа — тестовые данные со старыми id (`u_...`),
     их не импортировать (у пользователей будут новые uuid Supabase).
8. Деплой на Cloudflare Pages из GitHub, переменные `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`.
   В Supabase → Auth → URL Configuration указать адрес сайта.

### Контракт адаптера (что код прототипа вызывает)
```
db.doc(path)            → { get(), set(data), update(patch), delete(), onSnapshot(next, err) }
db.collection(path)     → { get(), limit(n) (возвращает себя), onSnapshot(next, err) }
  snapshot документа:    { id, exists, data() }
  snapshot коллекции:    { docs: [ {id, exists:true, data()} ], size, empty }
  get/onSnapshot должны отдавать одинаковые формы; onSnapshot — сразу текущее значение, затем
  обновления через Supabase Realtime (канал на таблицу docs, фильтр по path / collection).
  Ошибки бросать как объекты с полем code: 'invalid_argument' (нет прав, RLS), 'unavailable' (сеть).
user.id()      → auth.uid()               user.canEdit() → role in ('owner','mentor')
assets.upload(blob) → { id, url }  (загрузка в bucket assets, id = uuid без дефисов)
downloads.save({filename, data}) → обычное скачивание через Blob + <a download>
```
Пути, которые использует приложение: `cms/main` (настройки, главная), `cms/main/lessons/<id>`,
`cms/main/sections/<k>`, `cms/main/access/<uid>`, `trainees/<uid>`.

### Что заменить в коде прототипа
- `uiConfirm/uiPrompt/uiAlert` — оставить (собственные диалоги).
- Вход наставника по паролю → проверка роли.
- `history.replaceState`/hash-роутинг — оставить.
- `LOGO_FULL` и маленький логотип — вынести в `public/` как файлы.

## Приёмка этапа 1 (проверить вручную и Playwright-тестами)
- Регистрация абитуриента → он появляется в журнале наставника (вкладка «Журнал абитуриентов»).
- Наставник открывает/закрывает разделы галочками → у абитуриента разделы появляются/исчезают без перезагрузки.
- Наставник: загрузка фото в упражнение «Найди дефект», отметки, сохранение; абитуриент проходит упражнение.
- Лекция: блоки текст/слайдер/лента фото, лупа на весь экран.
- Замечание DES: форма, проверка, эталонный текст.
- Блиц-тест: вопросы наставника, засчитывается только отмеченный правильный ответ.
- Главная: конструктор блоков, обложки разделов.
- Абитуриент не может записать в `cms/*` и прочитать чужой `trainees/*` (проверить RLS запросом).
- CSV-журнал скачивается.

## Этап 2 (после запуска)
- Нормализовать БД: таблицы `lessons`, `exercises`, `progress`, `exam_results` вместо jsonb-документов;
  журнал наставника — SQL-представление с фильтрами.
- Админка ролей (owner назначает mentor) в интерфейсе вместо SQL.
- Резервные копии: еженедельный экспорт `docs` и bucket `assets`.
- Бесплатный проект Supabase ставится на паузу после 7 дней без запросов — для боевого режима
  либо регулярная активность, либо тариф Pro.

## Правила работы
- Язык интерфейса — русский. Тексты уроков и нормативов не менять без запроса.
- Не коммитить `.env` и service-role ключ.
- После каждого шага — запуск локально (`npm run dev`) и проверка сценария из приёмки.
